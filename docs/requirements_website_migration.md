### 0-1 ガイド HTML の性質（設計上いちばん効く事実）

**ガイド HTML は「Web ページ」ではなく「スマホ版 PDF を作るための原稿」である。**

- `<title>` が `大阪美食ガイド(スマホ版)`
- CSS に **`@page{size:120mm 240mm; margin:7mm 7mm 8mm;}`**＝**紙面サイズが固定**
- 本文の単位が `pt`（`font-size:10.5pt`）＝**画面ではなく印刷の単位**
- CSS は**全文インライン**で自己完結。画像は**相対パス**（`img/osaka/_map.png`）

**＝そのまま公開しても表示はされるが、画面幅に追従しない固定幅のページになる。** ここをどうするかが §4 の決定事項 D-3。

## 1. 目的

**Notion を廃し、Web サイトを美食ガイドの唯一の正面にする。**
Notion 側で解けなかった問題（`ai-memory` の `notion_map_embed_2026.md` §18-3 の B・C・F・I・K）を、
**対処ではなく消滅させる**のが移行の主目的。

| Notion で解けなかったこと | Web サイトでどうなるか |
|---|---|
| 地図の吹き出しに店名しか出せない（§17-3） | **消える。** `map/*.html` は既に一皿・写真2枚・地図リンクを出している |
| `カテゴリ` が単一選択で「ご当地グルメかつビール」を表せない（§18-3 C） | **消える。** 自前のデータ構造なので複数ジャンルを持てる |
| ページ冒頭のプロパティ欄を隠せない（同 F） | **消える。** 自分で書く HTML に不要な欄は無い |
| 「ジャンル」「カテゴリ」「章」の3系統が併存（同 I） | **消える**（ただし §4 の D-4 で名前を1つに決める必要がある） |
| 古いビューの絞り込みが API から消せない（§18-2） | **消える** |

## 2. スコープ

### 2-1 含む

- 全66都市に対話地図を付ける（現在5都市）
- 入口（トップページ）から各ガイド・各地図へ辿れるようにする
- 公開の自動化（元データを更新したらサイトが更新される）

### 2-2 含まない（明示的に外す）

## 3. 要件

### F-1 公開

- **F-1-1** 66冊のガイドが公開 URL で開けること。
- **F-1-2** 公開サイトの容量が **1GB 未満**であること（GitHub Pages の上限。出典＝[GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)）。
  **PDF 638MB と静止画地図 PNG 209MB を公開対象から外せば約407MB**で収まる。
- **F-1-3** 公開は**元データの更新から自動**で行われること（手作業の手順を残さない）。
- **F-1-4** 費用は**0円**であること。

### F-2 入口

- **F-2-1** トップページから、**地方 → 国/県 → 都市**の順で目的のガイドに辿り着けること。
- **F-2-2** 店名・ジャンルでの**横断検索**ができること（3,586店が対象）。
- **F-2-3** 各ガイドから、その都市の地図へ1タップで移動できること。逆も同じ。

### F-3 地図

- **F-3-1** **全66都市**に対話地図があること（現在5都市）。
- **F-3-2** ピンをタップすると **店名・ジャンル・一皿・写真（料理と外観）・Googleマップへのリンク**が出ること
  （**現在の `map/*.html` で既に満たしている**）。
- **F-3-3** **加えて、その店の記事（ガイド内の該当箇所）へのリンクが出ること**（現在の唯一の欠落）。
- **F-3-4** ジャンルで絞り込めること。**複数ジャンルを持つ店は、どちらで絞っても出ること**（Notion 版の欠陥の是正）。
- **F-3-5** 座標が無い店（現在67店）は**地図に出ないが、一覧には出る**こと。黙って消さない。

### F-4 表示

- **F-4-1** スマートフォンの画面幅で読めること（横スクロールが出ないこと）。
- **F-4-2** 写真が**遅延読み込み**であること（1冊あたり最大43MBの画像がある）。

### N-1 非機能

- **N-1-1** 既存の `notion/stores.json`（3,586店）を**唯一のデータの正**とし、地図・検索・一覧がすべてそこから生成されること。
- **N-1-2** ガイド本文の HTML（66冊）は**既存のものを再利用**し、書き直さないこと。
- **N-1-3** 公開されるサイトから、**Notion への依存が1つも残らない**こと。

## 4. 決定が要る事項（ユーザーに確認したいのはこの5件）

### D-1 ホスティング先 — **推奨: GitHub Pages**

| | GitHub Pages | Cloudflare Pages（Free） |
|---|---|---|
| 容量 | 公開サイト **1GB** | 明示なし |
| ファイル数 | 明示なし | **20,000**（現状 約4,944 で収まる） |
| 帯域 | 100GB/月（soft） | 記載なし |
| いまの状態 | **ワークフローが既に書いてある**（あとは有効化のみ） | 新規に設定が要る |

**推奨理由**＝**追加の設定がほぼ不要で、既に9割できている。** 容量も §3 F-1-2 の除外をすれば収まる。
出典: [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) ／ [Cloudflare Pages limits](https://developers.cloudflare.com/pages/platform/limits/)

### D-2 公開方式 — **推奨: まず「Deploy from a branch」で試し、本番は「GitHub Actions」**

`Settings → Pages → Source` の選択肢は2つだけ（出典＝[GitHub 公式](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)）。

| 選択肢 | 中身 | 向き不向き |
|---|---|---|
| **Deploy from a branch** | リポジトリのファイルをそのまま配る。選べる場所は**直下か `/docs` のみ** | **いますぐ試せる**（`map/` は8ファイルともコミット済み）。ただし**リポジトリ1.3GB がそのまま公開対象**になり、1GB 制限に弾かれる可能性がある（**未検証**） |
| **GitHub Actions** | ビルドしてから配る | **PDF と静止画 PNG を除いた約407MB だけを配れる。本番はこちら** |

**推奨の順序**＝**①まず Deploy from a branch にして、地図が本当に開くかを目で確認する（5分）→ ②確認できたら GitHub Actions に切り替える。**
①で1GB に弾かれたら、その時点で②へ飛ぶ。**どちらも設定画面のプルダウンを変えるだけで、後戻りできる。**

### D-3 ガイド本文をどう出すか — **推奨: 案B**

§0-1 のとおり、既存 HTML は**紙面サイズ固定（120mm×240mm）の PDF 原稿**である。

| 案 | 中身 | 手間 | 見え方 |
|---|---|---|---|
| **A そのまま公開** | 何もしない | **ゼロ** | 開けるが、**画面幅に追従しない固定幅**。スマホでは読めるが余白が不自然 |
| **B 印刷用 CSS を画面用に上書き** | ビルド時に `@page` と `pt` 指定を打ち消す CSS を1本足す | **小**（CSS 1ファイル・全66冊に共通で効く） | **スマホで自然に読める。本文・写真・構成は一切変えない** |
| C 本文を作り直す | テンプレートから再生成 | **大** | 自由だが、66冊ぶんの検証が要る |

**推奨＝B。** N-1-2（本文を書き直さない）を守りつつ F-4-1（スマホで読める）を満たせる。**PDF 版を作る機能も壊さない**（印刷用 CSS は残したまま、画面用を後から上書きするため）。

### D-4 ジャンルの呼び名を1つに決める

現在「ジャンル」「カテゴリ」「章（原文）」の3系統が併存している（§18-3 の I）。
**Web サイトでは1つに統一する必要がある。** どれを正にしますか。**推奨＝「ジャンル」**（ユーザーが 2026-09-12 の指摘で実際に使った語）。

### D-5 自動生成中の6冊（ローマ字題名・項目空欄・地図なし）をどう扱うか

47都道府県ガイドの自動生成が**週3回（月・水・金 01:00 JST）動き続けており、残り22県**。
現に不良な6冊（名古屋・豊田・津・四日市・草津・大津）がある。

| 案 | 中身 |
|---|---|
| **① 自動生成を止めてから移行** | 移行中に不良が増えない。**残り22県は移行後に手順を直してから再開** |
| ② 動かしたまま移行 | 移行後も不良が混ざり続ける |
| ③ 自動生成を Web サイト向けに作り直す | 一番きれいだが、移行と同時にやると範囲が広がりすぎる |

**推奨＝①。** ただし**止めるのはユーザーの資産に関わる操作**なので、**指示があるまで当方からは止めない。**
（この件の調査は別途バックグラウンドで実施中。次回発火日時が分かり次第、猶予日数とあわせて報告する）
